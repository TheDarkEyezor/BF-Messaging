# BF Messaging

A 1:1 chat application where every network command is **generated by a Brainfuck program**.

---

## Architecture

```
┌──────────────────────────────────────────────────────────┐
│  CLIENT  (client/client.py)                              │
│                                                          │
│  Python prompts user → feeds input to a BF program      │
│  BF program outputs a formatted protocol command         │
│  Client sends that command over TCP to the server        │
│  Server response is parsed and displayed                 │
│                                                          │
│  Background thread: prints +INCOMING push messages       │
│  in real-time while the user is at the menu              │
└─────────────────────┬────────────────────────────────────┘
                      │  TCP text protocol  (port 9999)
┌─────────────────────▼────────────────────────────────────┐
│  SERVER  (server/server.py)                              │
│                                                          │
│  asyncio TCP server — handles multiple clients           │
│  SQLite (messages.db) — users + message history          │
│  Routes SEND to recipient instantly if online            │
└──────────────────────────────────────────────────────────┘
```

### Brainfuck's role — command builders

Each user action maps to a `.bf` program.  
The program takes **plain user input on stdin** and emits a **protocol command on stdout**.

| Action | BF program | stdin fed by Python | BF stdout (→ server) |
|---|---|---|---|
| Register | `register_cmd.bf` | `alice\n` | `REGISTER alice\n` |
| Find user | `find_cmd.bf` | `bob\n` | `FIND bob\n` |
| Send message | `send_cmd.bf` | `bob\nhey there\n` | `SEND bob hey there\n` |
| Chat history | `history_cmd.bf` | `bob\n` | `HISTORY bob\n` |
| Quit | `quit_cmd.bf` | *(none)* | `QUIT\n` |

The BF programs work by:
1. Printing the command keyword character-by-character (hard-coded ASCII arithmetic).
2. Reading each stdin field and echoing it byte-by-byte until a newline is consumed.
3. Emitting the terminating `\n`.

## Protocol reference

```
Client → Server          Server → Client
─────────────────────    ──────────────────────────────────────────
REGISTER <username>  →   +OK Registered as alice
                         +OK Welcome back alice
                         -ERR Username must be alphanumeric

FIND <username>      →   +USER bob online
                         +USER bob offline
                         -ERR User 'bob' not found

SEND <to> <message>  →   +OK Message delivered to bob
                         -ERR User 'bob' not found
                         [push to bob]  +INCOMING alice 2026-03-10T12:00:00 hey!

HISTORY <username>   →   +HIST alice 2026-03-10T12:00:00 hey!
                         +HIST bob   2026-03-10T12:00:05 hi back
                         +END
                         +END No messages with bob

QUIT                 →   +OK Goodbye
```

## Quick start

**Terminal 1 — start the server**

```bash
cd "BF Messaging"
python server/server.py
```

**Terminal 2 — first user (Alice)**

```bash
python client/client.py
# username: alice
```

**Terminal 3 — second user (Bob)**

```bash
python client/client.py
# username: bob
```

Alice can now send Bob a message (option 2).  Bob will see it appear
instantly in his terminal, even while he's at the menu.

## Testing the BF programs directly

You can run any command builder from the shell to inspect its output:

```bash
# Print "REGISTER alice\n"
python brainfuck/interpreter.py brainfuck/register_cmd.bf "alice
"

# Print "SEND bob hello world\n"
python brainfuck/interpreter.py brainfuck/send_cmd.bf "bob
hello world
"
```

## How the BF read-until-newline loop works

Every field echo uses this short BF idiom:

```brainfuck
,----------[++++++++++.,----------]
```

Step by step:

| BF | Effect |
|---|---|
| `,` | Read one byte from stdin into the current cell |
| `----------` | Subtract 10 (ASCII value of `\n`) |
| `[` | Enter loop only if result ≠ 0 (i.e., not a newline) |
| `++++++++++` | Restore the original byte value |
| `.` | Output the byte |
| `,----------` | Read next byte and subtract 10 in one pass |
| `]` | Repeat until we consumed the newline |

After the loop the cell is 0.  A final `++++++++++.` emits the trailing `\n`
that terminates the protocol command.

## Design notes

* **No external dependencies** — pure Python 3.10+ standard library.
* **SQLite persistence** — the `server/messages.db` file survives restarts;
  history queries work across sessions.
* **Real-time delivery** — the server pushes `+INCOMING` to the recipient's
  open TCP connection immediately; the client's reader thread displays it
  without blocking the interactive menu.
* **BF as the serialisation layer** — all command strings that traverse the
  network are produced exclusively by Brainfuck programs.  The Python runtime
  never hard-codes a command string.
